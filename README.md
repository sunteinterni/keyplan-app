# Lighting Platform (Light Theory)

เว็บแพลตฟอร์มสำหรับทีมออกแบบแสงสว่าง: อัปโหลดแปลนลูกค้า → วางสัญลักษณ์โคมพร้อมรหัส LT → จัดการสเปค (รูป/รุ่น/ขั้ว/จำนวนหลอด/วัตต์/K/ราคา/ซัพพลายเออร์) → โยงวงจรและสรุป Lighting Load Schedule → คำนวณ BOQ + VAT 7% → Export **PDF A3 แนวนอน** (และ Excel)

## ฟีเจอร์
- โปรเจกต์ไม่จำกัด · หลายชั้น (เพิ่ม/ลบ/เปลี่ยนชื่อ/เปลี่ยนแปลน) · แปลนรับ PNG/JPG/PDF (เลือกหน้า PDF ได้)
- สัญลักษณ์ 6 แบบ: ดาวน์ไลท์, ไฟกิ่ง, สปอตไลท์+ลูกศร (หมุนทิศได้), โคมแขวน Pendant, ราง Tracklight, เส้นประ · สีแดง/น้ำเงิน/เขียว (ตั้งที่ระดับ “รหัสโคม” หรือปรับจากแผงด้านขวาตอนเลือกจุด)
- เปลี่ยนรหัสโคมของจุดที่วางแล้ว · ลาก/ย้าย · Delete เพื่อลบ · ซูมด้วยล้อเมาส์
- เลือกหลายจุด: Shift+คลิก, Shift+ลากกรอบ, Ctrl+A ทั้งชั้น → ย้าย/โยงวงจร/เปลี่ยนรหัส/ลบทีเดียว · Undo/Redo (Ctrl+Z / Ctrl+Y) ทุกการแก้ไขบนแปลน
- ตั้งสเกลจากระยะจริง 2 จุด → ความยาวไฟเส้น/ราง (เมตร) นับเข้า BOQ อัตโนมัติ · รางใส่จำนวนหัวสปอตได้
- โยงวงจร: ตั้งชื่อวงจร (LV-01…), คลิกโคมตามลำดับ → เส้นโยงบนแปลน + ตาราง Load Schedule (ชุด/เมตร/วัตต์/แอมป์/เบรกเกอร์)
- ใบเสนอราคา: ราคาเว้นว่างได้ (“รอราคา”), ส่วนลด, ค่าติดตั้ง, VAT ปรับได้ (ค่าเริ่มต้น 7%)
- ตรวจก่อนส่ง: ขาดรุ่น/ราคา, จำนวนไม่ตรงสเปคชีท, เส้นที่ยังไม่ตั้งสเกล, K ไม่ตรงกัน, โคมที่ยังไม่เข้าวงจร
- คลังสเปคโคมกลางข้ามโปรเจกต์ (เมนู “คลังโคม”): นำเข้าโปรเจกต์เป็นสำเนาพร้อมรูปและราคา, เมื่อคลังถูกแก้ โปรเจกต์เห็นป้าย “อัปเดต” และเลือกอัปเดตหรือข้ามได้, บันทึกโคมจากโปรเจกต์เข้าคลัง / ส่งข้อมูลใหม่กลับคลัง · ทุกคนเพิ่ม/แก้ ลบได้เฉพาะผู้ดูแล
- ล็อกอินรายบุคคล (ผู้ดูแลเพิ่มสมาชิกได้)

## รันบนเครื่อง
```bash
npm install
npm run build        # สร้างหน้าเว็บ
npm start            # http://localhost:3000  (ครั้งแรกจะให้สร้างบัญชีผู้ดูแล)
npm run seed:demo    # (ไม่บังคับ) ใส่โปรเจกต์ตัวอย่างสมมติ [PLACEHOLDER] Residence
```
พัฒนาแบบ hot-reload: `npm run dev:server` และ `npm run dev:web` (เปิด http://localhost:5173)
ต้องมี `poppler-utils` (คำสั่ง `pdftoppm`, `pdfinfo`) ถ้าจะอัปโหลดแปลนเป็น PDF — macOS: `brew install poppler` · Ubuntu: `apt install poppler-utils`

ทดสอบ: `npm test` · ตรวจชนิดข้อมูล: `npm run typecheck`
ฟอนต์ PDF: `npm run fonts` แปลงไฟล์ WOFF จาก @fontsource เป็น TTF ใน `server/fonts` (รายชื่ออยู่ใน `server/fonts.ts`) ไฟล์ TTF ถูก commit ไว้แล้ว รันใหม่เฉพาะเมื่อเพิ่มหรืออัปเดตฟอนต์

## Deploy (ตัวเลือกที่ง่ายที่สุด: Railway)
ข้อมูลทั้งหมดอยู่ในโฟลเดอร์ `DATA_DIR` (ฐานข้อมูล SQLite + รูปที่อัปโหลด) จึง **ต้องผูก Volume** ไม่งั้นข้อมูลหายตอน deploy ใหม่

1. อัปโหลดโปรเจกต์นี้ขึ้น GitHub (repo ส่วนตัว)
2. railway.com → New Project → Deploy from GitHub repo (ตรวจพบ `Dockerfile` ให้อัตโนมัติ)
3. แท็บ **Volumes** → Add Volume → Mount path: `/data`
4. แท็บ **Variables** → เพิ่ม `SESSION_SECRET` = ข้อความสุ่มยาว ๆ (เช่น `openssl rand -hex 32`)
5. แท็บ **Settings → Networking** → Generate Domain → เปิดลิงก์ → สร้างบัญชีผู้ดูแลคนแรก → เพิ่มสมาชิกทีมที่เมนู “ทีม / บัญชี”

> “ใช้ภายในองค์กรเท่านั้น”: ระบบมีล็อกอินทุกหน้า ใครไม่มีบัญชีเข้าไม่ได้ แต่ URL ยังเปิดจากอินเทอร์เน็ตได้ ถ้าต้องการจำกัดวง IP/VPN ให้วางไว้หลัง Cloudflare Access / Tailscale หรือรันบนเซิร์ฟเวอร์ภายในด้วย `docker run -p 3000:3000 -v lpdata:/data -e COOKIE_SECURE=0 lighting-platform` (ใช้ `COOKIE_SECURE=0` เมื่อเข้าผ่าน http ธรรมดา)

### ทางเลือก: Fly.io
```bash
fly launch --no-deploy --copy-config      # แก้ชื่อ app ใน fly.toml ก่อน
fly volumes create lp_data --size 1 --region sin
fly secrets set SESSION_SECRET=$(openssl rand -hex 32)
fly deploy
```

## ตัวแปรสภาพแวดล้อม
| ชื่อ | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `DATA_DIR` | `data` (Docker: `/data`) | ที่เก็บฐานข้อมูล + ไฟล์อัปโหลด |
| `SESSION_SECRET` | สร้างเองและเก็บใน `DATA_DIR/.session-secret` | กุญแจเซ็นคุกกี้ล็อกอิน |
| `COOKIE_SECURE` | `1` ใน Docker | `1` = ส่งคุกกี้เฉพาะ HTTPS · ตั้ง `0` ถ้าใช้ http |
| `PORT` | `3000` | พอร์ต |

## สำรองข้อมูล
คัดลอกทั้งโฟลเดอร์ `DATA_DIR` (หรือใช้ Volume snapshot ของ Railway/Fly) — ไฟล์สำคัญคือ `app.db` และ `uploads/`
